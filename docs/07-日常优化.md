# 需求文档：题目过滤 + 低年级自定义输入组件

## 背景

算道是一个面向小学生的 AI 数学练习网站。现有题目支持选择题、填空题。
低年级（1-3 年级）学生普遍不具备中文键盘输入能力，需要对题目和交互进行适配。

---

## 一、题目数据结构改造

### 目标

现有题目 JSON 中，填空题没有区分"数字填空"和"中文/拼音填空"。
需要通过 **bash 脚本 + 大模型** 批量为现有题目的每个空（blank）打上 `input_type` 标签。

### 新增字段

在每道题的每个空（blank）上新增字段：

```ts
input_type: 'number' | 'choice' | 'text'
// number  = 纯数字答案（如：12、3.5）
// choice  = 选择题选项（如：A/B/C/D）
// text    = 需要中文、拼音或字母打字输入
```

### 数据结构示例

```json
{
  "id": "q_001",
  "type": "mixed",
  "content": "小明有 __ 个苹果，他的妈妈姓 __，一共有 __ 个水果",
  "blanks": [
    { "id": "b1", "input_type": "number", "answer": "5" },
    { "id": "b2", "input_type": "text",   "answer": "王" },
    { "id": "b3", "input_type": "number", "answer": "10" }
  ]
}
```

> 原有纯选择题，blanks 中每个选项的 `input_type` 均为 `"choice"`。
> 原有纯数字填空题，`input_type` 均为 `"number"`。

### 脚本要求

1. 读取现有题目 JSON 文件（路径通过参数传入）
2. 对每道题的每个 blank，调用大模型判断 `input_type`
3. 大模型 prompt 示例：

```
你是一道小学数学题的答案类型判断器。
给定一道题目和某个空的正确答案，判断该空的输入类型：
- 如果答案是纯数字（整数或小数），返回 "number"
- 如果答案是从选项 ABCD 中选择，返回 "choice"
- 如果答案需要输入中文、拼音、字母等，返回 "text"
只返回一个单词，不要解释。

题目：{question_content}
该空答案：{answer}
```

4. 将结果写回 JSON，新增 `blanks[].input_type` 字段
5. 支持断点续跑（已有 `input_type` 的 blank 跳过）
6. 输出处理进度和失败记录到日志文件

## 二、摸底考试入口：年级选择页改造

### 目标

用户在摸底考试页面选择 **1 年级、2 年级、3 年级** 时，显示以下过滤选项：

### 新增 UI 控件

```
[ ✓ ] 过滤需要中文/拼音打字的填空题
      （如果您的孩子不会中文打字，建议开启）
```

- **默认状态**：选择 1-3 年级时，**默认勾选**
- 选择 4-6 年级时，不显示此选项
- 用户可手动取消勾选

### 过滤逻辑

```ts
// 判断一道题是否应被过滤
function shouldSkip(question: Question, filterChineseInput: boolean): boolean {
  if (!filterChineseInput) return false
  // 只要题目中存在任意一个 text 类型的 blank，整题跳过
  return question.blanks.some(b => b.input_type === 'text')
}
```

> ⚠️ 注意：不能只过滤"那个空"，必须整题跳过，否则题目逻辑不完整。

## 三、自定义输入组件（低年级适配）

### 触发条件

同时满足以下三个条件时，禁用原生键盘，启用自定义输入组件：

1. 当前年级为 1-3 年级
2. 用户已开启"过滤中文填空"选项
3. 当前设备检测为 **H5 / Pad / App（移动端）**

> 设备检测参考：UA 判断 + 屏幕宽度（≤ 1024px 视为移动端），优先使用已有的设备检测工具函数。

### 交互设计

#### 布局

```
┌──────────────────────────────────┐
│           题目内容区              │  ← 键盘弹起时整体上移，保证当前焦点可见
│   3 + __ = 12    答案选（__）     │
│         [当前聚焦的空高亮]        │
├──────────────────────────────────┤
│         自定义输入键盘            │  ← 底部浮层，占屏幕高度约 40%
│                                  │
│  数字模式：          选择模式：   │
│   7   8   9          A    B      │
│   4   5   6          C    D      │
│   1   2   3                      │
│   .   0   ⌫                      │
└──────────────────────────────────┘
```

#### 键盘类型切换规则

| 当前聚焦空的 `input_type` | 键盘显示 |
|---|---|
| `number` | 九宫格数字键盘（含小数点和退格） |
| `choice` | ABCD 四个大按钮（两行两列） |

#### 焦点流转

- 点击题目中某个空 → 键盘弹出并切换到对应类型
- 填写完当前空 → 自动聚焦下一个空（键盘平滑切换，**不收起再弹**）
- 所有空填写完毕 → 键盘收起，出现"提交"按钮

#### 动画要求

- 键盘弹出/收起：底部滑入滑出，duration 250ms，ease-out
- 键盘类型切换（数字 ↔ ABCD）：内容渐变过渡，duration 200ms
- 当前聚焦空：高亮描边动画

#### 组件接口（伪代码）

```ts
interface Blank {
  id: string
  input_type: 'number' | 'choice'
  options?: string[]  // choice 时传入，如 ['A','B','C','D']
  value: string
  onChange: (value: string) => void
}

interface CustomKeyboardProps {
  blanks: Blank[]
  visible: boolean
  onClose: () => void
}
```

> 组件对外只暴露 blanks 列表，内部自行管理焦点状态和键盘类型切换。
> 后续新增题型只需新增对应键盘布局，不改动现有逻辑。

## 五、验收标准

1. **脚本**：处理 100 道题后，所有 blank 均有 `input_type` 字段，日志记录失败条数
2. **过滤**：选 1-3 年级 + 开启过滤后，出题队列中不出现含 `text` 类型 blank 的题目
3. **键盘**：移动端 + 低年级 + 开启过滤时，点击数字空弹出九宫格；点击选择空弹出 ABCD；切换时不闪烁
4. **布局**：键盘弹出时题目内容完整可见，不被遮挡
5. **桌面端**：不触发自定义键盘，使用原生输入
